# 二、架构设计

## 2.1 总体架构

WordCraft 采用**严格分层 + 一切皆命令**两项核心架构决策。

### 分层（L0–L6，由 `cargo xtask layers` 在 CI 强制）

```
L6  ui-egui ───────────── Word 风格前端（ribbon/画布/对话框/侧栏/i18n）
L5  mcp ───────────────── MCP 服务器；zotero；control-key
L4  engine ────────────── Session、undo/redo、命令注册表、I/O 分发
L3  render · pdf ──────── 光栅化 / PDF 导出（共用显示列表）
L2  layout · docx · docbin · formats · insights ─ 排版、OOXML、.doc、格式桥、写作洞察
L1  doc · fonts · proof ─ 文档模型、字体整形、拼写
L0  geom ──────────────── 单位与几何
apps  wordcraft（桌面）/ wordcraft-cli / wordcraft-web
```

规则：低层不得依赖高层；L6 以下禁止依赖 egui/winit/rfd。这使得排版引擎、文档模型可以
在无 GUI 环境下测试与复用（CLI、MCP、服务端场景全部成立）。

### 一切皆命令

每个用户动作都是一条 `CommandSpec { id, label, location, shortcut, params, mutates, enabled, run }`
注册进 `Registry`；`Session::run(id, params)` 是唯一执行入口。由此：

- ribbon 按钮、菜单、快捷键、CLI、MCP 工具、控制端口**共用同一实现**；
- undo/redo、命令回放（Repeat）、宏录制自动获得；
- `mutates=false` 的纯命令（如本实践的 `review.insights`）不进撤销栈。

## 2.2 主要模块与功能

| 模块（层） | 功能 | 规模 |
|---|---|---|
| `geom`（L0） | 点/缇/EMU/英寸单位、旋转矩形、测量解析 | 335 行 |
| `doc`（L1） | 文档中心模型 `Document`：多故事（body/脚注/页眉/文本框…）、段落/Run/表格/分节/样式/编号/字段/公式树、编辑原语 | 11,192 行 |
| `fonts`（L1） | 字体库（内置 OFL + 系统扫描）、HarfRust 整形、Word 字体替换规则、OpenType MATH | 2,659 行 |
| `proof`（L1） | 拼写检查（公有领域词表）、规则语法、Liang 连字 | 1,427 行 |
| `layout`（L2） | 断行、分页、分栏、表格、页眉页脚、浮动环绕、公式排版、命中测试 → 产出显示列表 | 12,628 行 |
| `docx`（L2） | ECMA-376 OOXML 读写（加密、OMML、图表、VBA 保留） | 14,550 行 |
| `docbin`（L2） | Word 97-2003 `.doc` 只读（FIB/piece table/FKP） | 4,397 行 |
| `formats`（L2） | ODT/RTF/HTML/Markdown/LaTeX/TXT 经中间模型 `Flow` 桥接 | 10,707 行 |
| `insights`（L2，本实践新增） | 文本统计、可读性指标、写作问题检测、报告模型 | ~1,400 行 |
| `render`（L3） | vello_cpu 光栅化：页面位图、缩略图 | 1,204 行 |
| `pdf`（L3） | krilla PDF 导出：字体子集、可选中文本、Tagged PDF | 2,125 行 |
| `engine`（L4） | `Session`、undo/redo、**命令注册表**、Word 功能目录、I/O 分发 | 21,868 行 |
| `mcp`（L5） | MCP 服务器：每条命令一个工具，可桥接运行中的桌面应用 | 972 行 |
| `ui-egui`（L6） | ribbon/画布/面板/对话框/i18n（9 语言目录） | 21,821 行 |

## 2.3 模块间接口（关键跨层类型）

| 生产者 → 消费者 | 接口类型 | 说明 |
|---|---|---|
| doc → layout | `&Document` + `StoryRef` | 只读访问文档模型；`Paragraph.rev` 修订计数器供缓存失效 |
| layout → render/pdf | `DisplayList`（`Placed` → `Draw`） | 版式结果的中立表示，两端共用 |
| docx/formats → doc | `Document`（构造/转换） | 各适配器把外部格式归一到文档模型 |
| engine → 全部 | `CommandSpec` + `Registry` | 能力注册；`Session::run` 唯一入口，返回 `Result<Value, String>` |
| engine → ui | `ViewState`（serde） | 视图开关的持久化状态，UI 读写、会话保存 |
| layout → ui | `hit(Dp, Point) → Hit` | 命中测试，把屏幕坐标映射回文档位置 `Pos{story, path, off}` |
| insights → engine/ui | `InsightsReport`（serde JSON） | 报告模型：统计 + 指标 + findings（附跳转 `pos`） |
| fonts → layout | shaping runs | HarfRust 整形后的字形串与度量 |

## 2.4 数据流

```
.docx/.doc/.odt/… ──(适配器)──► Document（唯一权威模型）
                                     │ Session::run(命令)（undo/redo 包裹）
                                     ▼
                                  Layout（缓存：段落级记忆化，Paragraph.rev 失效）
                                     │ DisplayList
                          ┌──────────┴──────────┐
                          ▼                     ▼
                       render（位图）          pdf（导出）
```

编辑命令修改 `Document` 后，仅 `rev` 变化的段落重新排版（增量），显示列表随后被光栅化或
导出 PDF——这是 WordCraft 在纯 CPU 下保持流畅的关键。

## 2.5 横切设计

- **无 panic 纪律**：全工作区 `#![deny(clippy::unwrap_used, expect_used, panic, unimplemented, todo, unreachable)]`（测试豁免）；危险路径由 `catch_unwind` 兜底，命令失败整体回滚。
- **i18n**：UI 字符串一律过 `tl!` 宏，9 个 TSV 目录，缺条目回退英文；有覆盖完整性测试。
- **测试**：单元 + 快照 + proptest（`geom`/`doc` 不变量）+ 忽略型 UI 审计（伪语言扫描未翻译文本）。
