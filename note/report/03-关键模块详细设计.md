# 三、关键模块详细设计 —— layout 排版引擎

> 标注对象：`crates/layout/src/`（8 个文件，约 12,600 行）。本实践对其完成 **+2,038 行中文
> 代码标注**（纯注释，经 `git diff` 逐文件验证不含代码改动），标注版见 `master` 分支第二个版本。

## 3.1 模块职责与业务流程

layout 接收只读的 `Document`，产出与渲染后端无关的**显示列表**（`DisplayList`），被位图渲染
（`render`）与 PDF 导出（`pdf`）共用。一次完整排版的主循环（`lib.rs`）：

```
输入 Document ─► 逐「节(Section)」迭代：
  1. 解析页面几何（纸张、页边距、分栏）      ← geom 单位换算
  2. 排页眉/页脚（页码字段求值）             ← fields.rs
  3. 逐段落整形：                            ← para.rs
     a. 取段落文本 → HarfRust 整形（fonts 层）
     b. first-fit 断行（UAX #14 断行类 + 连字点 + kinsoku 禁则）
     c. 制表位惰性求解（pending_tab）
     d. 双向文本：逻辑序 xs 与视觉序 vis 双表示
  4. 表格布局（列宽分配、跨页行拆分）        ← table.rs
  5. 浮动对象放置与文本环绕
  6. 脚注/尾注分配到当页
  7. 公式排版（GlyphPart 伸展装配）          ← math.rs
  8. 页满 → 分页，写显示列表
输出 DisplayList（含每段的命中区域）          ← display.rs / hit.rs
```

**增量性**：`Document` 中每个段落带修订计数器 `rev`；`LayoutCache` 以段为粒度记忆化排版
结果，只重排内容变化的段落。这是整个应用流畅度的基础，也是我给 `lib.rs` 标注时重点展开
的部分。

## 3.2 关键算法

### （1）first-fit 断行（para.rs）

- 预计算每个字符的 **UAX #14 断行类**，空格处积累"可断窗口"；
- 行宽溢出时回退到最近的可断点；CJK 逐字可断，但套用 **kinsoku 禁则表**（kinsoku.rs：
  行首禁字如 `」？！`，行尾禁字如 `「`）前后调整；
- 连字：向 proof 层查询 Liang 连字点，作为附加断点（拉丁长词必需）；
- 每行结束时计算对齐（两端对齐把剩余空隙分配到空格，CJK 再分配到字间）。

复杂度 O(n)（无全局最优解的 DP/Knuth-Plass——alpha 阶段以可预测性换最优性，代码注释中
标明了这一取舍）。

### （2）制表位惰性求解（pending_tab）

制表符的位置依赖"同一行里后续内容是否会越过下一个制表位"（Word 语义）。实现把 tab 记为
`pending_tab` 挂起，等后续 run 宽度确定后再回头求解 tab 的实际 x——避免了前置扫描。

### （3）双向文本双表示（xs / vis）

Bidi 重排后视觉顺序 ≠ 逻辑顺序。layout 同时维护逻辑片段表 `xs` 与视觉序 `vis`：
光标移动/命中测试用逻辑序，绘制用视觉序。这是 UAX #9 的工程化落地。

### （4）表格跨页行拆分（table.rs）

行高超过剩余页高时，把行拆到两页：按行内各单元格的断行结果找"可拆分线"，两侧补边框
（`region` 边框片段），表头按配置在新页重复。

### （5）公式伸展装配（math.rs）

OpenType MATH 表给出 `GlyphPart`（可垂直伸展的部件族）；按目标高度从部件族装配，连接
处的重叠量（connector overlap）取三者最小可用值，保证伸展符号（括号/根号/大括号）无缝。

### （6）命中测试（hit.rs）

`hit(Dp, Point)` 在显示列表上做区间查找，把屏幕坐标映射回 `Pos { story, path, off }`——
它是点击定位、选择拖拽、拼写下划线点击的共同入口。

## 3.3 数据设计

| 类型 | 作用 |
|---|---|
| `DisplayList` | 每页 `Placed` 项（文本 run / 线 / 图 / 裁剪组）的扁平列表，渲染零重算 |
| `LayoutCache` | `段落 rev → 排版结果` 记忆化表；文档编辑只 bump 受影响段落的 rev |
| `Line` / `Run` | 行 = 视觉序 run 序列；run 携带字形、基线、方向 |
| `Pos { story, path, off }` | 全模块统一的文档位置（故事 + 块路径 + 字节偏移），本实践新增的 findings 跳转复用它 |
| `GlyphPart` | MATH 伸展部件（顶部/中段/底部 + 连接重叠） |

## 3.4 开发经验与技巧（读码所得）

1. **层强制脚本化**：`xtask layers` 用一张表声明依赖规则并在 CI 卡住——架构约束不靠自觉
   靠工具。本实践新增 `insights` crate 时同步登记了该表（L2）。
2. **no-panic 纪律**：`deny(unwrap/expect/panic/…)` 全工作区生效，测试内豁免。排版器面对
   敌意输入（畸形字体、超长词、空文档）只能返回空结果。我的 `insights` crate 沿用了同一
   门禁。
3. **段落级增量 + 修订计数器**：不引入"脏区"结构，一个 `u64 rev` 就让缓存失效问题退化为
   整数比较——极简且正确。
4. **显示列表中立性**：layout 不知道位图与 PDF 的存在，两端共享一份版式结果——新增渲染
   后端（如 WebGPU）无需触碰排版。
5. **纯命令划分**：`mutates=false` 的命令（打开对话框、查询类）不进撤销栈；`Session::run`
   在入口处分流。`review.insights` 因此天然免撤销。
6. **测试贴近敌意输入**：layout 与 insights 的测试都以"畸形输入不 panic"为一等公民，而非
   只测快乐路径。
